# Make the collector guest merge all-or-nothing

Signing in as a non-player creates a collector identity and moves that phone's guest
pulls onto it. Today the move happens in three separate database calls, so a hiccup
between them can leave part of the collection committed onto an identity the code then
retires — those cards are gone for good and a retry cannot find them.

## Fix

Add one database function that performs all three moves inside a single transaction,
and call it once per guest instead of the three calls.

### Migration

New file `supabase/migrations/<timestamp>_merge_guest_for_collector.sql`:

- `CREATE OR REPLACE FUNCTION public.merge_guest_into_collector(_participant_id uuid, _guest_id uuid) RETURNS void`
- `LANGUAGE plpgsql`, `SECURITY DEFINER`, `SET search_path = public`.
- Body, in this order (matching `attach_device_to_player`, whose comment explains why
  packs precede milestone claims):
  1. `SELECT id ... FROM public.participants WHERE id = _participant_id FOR UPDATE`,
     raise if missing — same lock ordering as the other merge paths, so it cannot
     deadlock against them.
  2. `PERFORM public.claim_guest_secrets(...)`
  3. `PERFORM public.claim_guest_packs(...)`
  4. `PERFORM public.claim_guest_streak_milestones(...)`
- Deliberately does **not** touch `account_identities`: the collector flow owns that
  binding and its restore path.
- `REVOKE ALL ... FROM PUBLIC, anon, authenticated;` and
  `GRANT EXECUTE ... TO service_role;`
- Idempotent so `tests/db` can replay it from empty.

Types are regenerated by the platform after the migration so the new function is typed.

### Server change

`src/lib/collector.server.ts` — `mergeGuests` loops over the guest ids and makes one
`supabaseAdmin.rpc("merge_guest_into_collector", ...)` call per guest, throwing on
error exactly as now. The existing restore/retire catch block in `createCollector` is
unchanged; with the merge atomic, a failure leaves the guest's rows untouched and the
retry replays cleanly.

Comment explains why it is one call: a partial merge nulls `guest_id`, so the retry
that the catch block sets up would find nothing to reclaim.

### Tests

- `tests/db/collector-merge.test.ts` (new): a guest with a secret pull, a pack open and
  a milestone claim; `merge_guest_into_collector` moves all three; a call naming a
  missing participant raises and leaves every row still on the guest; `anon` and
  `authenticated` cannot execute it.
- `src/lib/collector.server.test.ts` / existing collector tests: update the mocked RPC
  expectations from the three `claim_guest_*` names to the single new one, keeping the
  merge-failure restore assertions.

## Verification

`bun run format`, then `bun run lint`, `bun run typecheck`, `bun run test`,
`bun run test:db`. No new dependencies, no other flow changed.

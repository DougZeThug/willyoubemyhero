# Verification: foundations

How to run this file: bring the surface up the way [the protocol](README.md)
says — `bun run dev` and open it on a phone on the same network, or use the
deployed app — and confirm `git rev-parse --short HEAD` reads `b46f330` before
recording anything. A fresh state for this cluster means clearing site data for
the origin, which removes every `wwbh:` key in browser storage
(`wwbh:guest-token`, `wwbh:member-token`, `wwbh:member-name`, `wwbh:was-member`,
`wwbh:admin-token`, `wwbh:device-id`, `wwbh:vault-favourites`,
`wwbh:vault-layout`, `wwbh:trade-seen`, `wwbh:trophy-seen`, `wwbh:sfx-muted`,
`wwbh:guest-name`, the `wwbh:v…` art-URL snapshots and `wwbh-active-run`) and
both IndexedDB databases, `wwbh-cards` (the collection and the day's pack) and
`wwbh-combine` (a run in progress on the timing console). Clear deliberately
rather than between every item: it mints a new guest with a fresh daily pull and
loses whatever that guest held. Preferences must be at their defaults — OS
reduced motion off, card sound unmuted, Tilt off, the browser's motion
permission not yet granted, and the device clock set automatically and correct.
Unless a row says otherwise, assume exactly one combine is active and the dust
switch is off. Device values in this file: **phone** is the real surface and the
default; **desktop** is a wide browser, used here only where a row needs
devtools or a wide layout; **guest** is a browser with site data cleared and no
player claimed; **member** is a browser holding a member token claimed from a
paper code; **account** is signed in with email and password; **commissioner**
is an admin session from the PIN or an admin account, and it lasts 12 hours;
**second device** is genuinely a second handset, never a second tab, because a
second tab shares storage and IndexedDB and a second device shares only what the
server holds; **second person** is somebody else's member session; **offline**
is airplane mode on the handset, because devtools' offline toggle does not fail
an in-flight websocket the way losing the radio does; **reduced motion** is the
OS-level setting; **race day** marks items that can only honestly be checked
while a combine is actually running.

Not checkable by hand:

- Whether the four guards are the complete set, and whether a new handler could ship without one — it is a source-level assumption, not something a screen shows ([Open questions and verification](../foundations/identity-and-sessions.md#open-questions-and-verification)).
- That a one-letter prefix inside the signed payload is what stops a signature being transplanted between the guest and member schemes ([Edge cases](../foundations/identity-and-sessions.md#edge-cases)). Both tokens are four parts on the outside; the difference is inside a signature and only the unit tests can see it.
- The hourly member-token re-check and the per-minute admin re-check: an admin session would have to be watched for twelve hours and a member's for ninety days to see one lapse without a reload ([Open questions and verification](../foundations/identity-and-sessions.md#open-questions-and-verification)).
- Whether a failed guest-to-member move leaves any visible trace, which needs the move to be made to fail on purpose ([It settles](../foundations/identity-and-sessions.md#it-settles)).
- Whether "a collector" — a signed-in account with no roster player — is reachable at all without the league issuing one ([Edge cases](../foundations/identity-and-sessions.md#edge-cases)).

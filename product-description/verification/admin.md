# Verification: admin

How to run this file: unlock the console once at the start of a session and work
down — `/admin`, PIN or admin account, and confirm the header shows a Lock
control before starting. **Most of this file must be run against a throwaway
event, not the league's real combine.** Six kinds of item here destroy something
that cannot be put back: issuing member codes rotates live paper slips
(ADM-68 to ADM-71, and the triage entries B-01 and B-02 are exactly that
hazard), Reset combine deletes every recorded run (ADM-38, ADM-74), Discard
throws away a real person's time (ADM-36), deleting a result or a station
removes splits (ADM-56, ADM-57, ADM-92, ADM-99), removing a secret card deletes
art with no undo (ADM-113, ADM-114), and a grant or an ownership attach changes
somebody's collection with no control anywhere that reverses it (ADM-152,
ADM-155). Every one of those items says "throwaway event" in its Setup, and the
Setup is not advisory. **Never run an item that issues or rotates member codes
against the roster people are holding paper for** — the plaintext is shown once
and the old slips die the moment the list appears. Create a second event, add
two or three dummy participants to it, and unlock the console against that
event's PIN; the token names one event, so a throwaway token cannot reach the
real combine. For the destructive items on the roster, use dummy participants
nobody holds a card for. Device values: **phone** is the real surface and the
default; **desktop** is only for the always-open panels and the drag-and-drop
paths; **commissioner** means a valid admin token for the event under test;
**second device** means a genuinely second handset, since two tabs on one phone
share the stored token and the stored run; **offline** means airplane mode on
the handset, not the devtools toggle, which does not fail an in-flight websocket
or a POST the same way; **race day** items can only be checked honestly while a
combine is actually being run.

Not checkable by hand:

- **What the screen does with no active event at all** ("the screen never gets past
  Loading…", [Arrive](../admin/getting-in.md#arrive)). Producing it means having no
  active event anywhere, which cannot be staged on a throwaway event and would
  take the real combine off every player's phone.
- **That the twelve hours are wall-clock** ([Modifiers](../admin/getting-in.md#modifiers)).
  ADM-13 fakes the expiry; watching a real session end takes twelve hours and is
  worth doing only alongside a real combine.
- **Whether the account door retries after a sign-in performed on the gate itself**
  ([Open questions](../admin/getting-in.md#open-questions-and-verification)). The
  once-per-account latch is page state with no visible surface; a hand tester
  cannot distinguish "did not retry" from "retried and was refused silently".
- **That no screen other than `/admin` and the Live bar reads the admin token**
  ([Open questions](../admin/getting-in.md#open-questions-and-verification)). A
  negative over every screen in the app; this is a code search, not a pass.
